Setup

Four commands, two permissions macOS asks for, and one it never will.

Install

cd ~/vortex && git pull
./macos-daily-welcome/install.sh
daily-welcome --set-key
orbit selftest
The installer needs swiftc. If it says so, run xcode-select --install and try again - without it there is no menu bar app, and with no app macOS never asks for anything.

Permissions

Asked for once

Microphone and Speech Recognition for the wake word. Reminders, Calendar, Contacts, Mail, Messages, Notes for reading and acting. Accessibility for typing and window commands.

Never asked for

Reading Messages needs Full Disk Access, which macOS will not prompt for. Add ~/Applications/DailyWelcome.app under Privacy and Security, Full Disk Access.

Grants belong to whichever app is asking. Allowing your terminal does not allow the menu bar app. If something was refused once, macOS remembers - daily-welcome --reset-permissions makes it ask again.

When the wake word doesn't fire

A made-up name isn't in any recogniser's vocabulary, so it comes back as whatever real words it resembled. Three fixes, in order:

orbit listen heard                    # what it actually heard you say
orbit listen alias "or bit"           # accept that as the wake word too
orbit listen wake "hey computer"      # or use words it already knows
Server recognition is the default because on-device recognition is markedly worse at unfamiliar words. Turn it back on in the console if you would rather the audio never left the Mac.

This site

cd macos-daily-welcome/web/orbitai
vercel deploy --prod

orbit console --allow https://your-project.vercel.app
orbit console --bridge                # prints the pairing token
The page runs in your browser and talks straight to your Mac. A browser will let any site reach localhost, so the bridge refuses anything without the token. Safari blocks HTTPS pages from reaching local addresses entirely - there, run orbit console and use the copy served from the Mac.
OrbitAI runs on your Mac. This page only ever talks to it directly.
